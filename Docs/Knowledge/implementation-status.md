# Implementation status

- Player two-hit damage, death and checkpoint respawn (2026-10-04): `BP_FPCharacter.Health` is a two-hit remaining-count (`2 → 1 → 0`). Positive Unreal Damage is accepted once per 0.9 seconds of real time, independent of global time dilation. The first accepted hit enables `M_PlayerDamageVignette`, whose screen-space rectangular edge mask replaces the former circular lens-shaped vignette, and holds a restrained dark-red camera tint. F6 toggles a runtime-only global player invincibility switch by changing the player's native `Can Be Damaged` property; ON rejects every Unreal Damage source before `Event AnyDamage`, OFF restores normal damage, and neither state is saved. The lethal hit sets `IsPlayerDead`, exits the time ability and restores world time, disables input and movement, zeros velocity, then teleports to the latest cached checkpoint both before the 0.65-second fade delay and again immediately before control/movement are restored. This prevents KillZ or residual falling from carrying the pawn away during the death window. Respawn restores Health, damage acceptance, walking/input and clears the vignette/fade. The cache initializes from the normal startup load result and refreshes whenever the existing `BP_AutoSavePoint` save path runs; the checkpoint asset and `SG_Character.PlayerTransform` persistence format remain unchanged. PIE passed F6 block/re-arm, first-hit feedback with the new material, same-frame checkpoint relocation, delayed checkpoint reassertion and full state reset. Cold compile/save and scoped runtime logs contained no task-related Blueprint, Python or material errors.
