# QTE 触发与遮挡修复（2026-10-22）

状态：已在 `dev/wingshing` 重新应用分支切换后丢失的修复。人工完整试玩验收仍待完成，恢复后的验证见下文。

## 原因与修复

- `AC_TimeAbility.ScanProjectileThreats` 的失败分支会隐藏 HUD。敌弹 BeginPlay 会请求扫描，第二次扫描落在 0.1 秒冷却内时，可能隐藏仍激活的 QTE。新增激活窗口入口保护；窗口维持函数继续负责超时和取消。
- `EvaluateProjectileThreat` 原先仅计算相对运动、胶囊范围、时间和视野，没有检查沿途掩体。候选通过后，沿实际弹丸速度到预测最近点做 Sphere Trace By Profile，使用弹丸碰撞组件的半径、移动忽略列表和经核对匹配的 `Projectile` 命名预设，并忽略弹丸自身。无阻挡或第一阻挡为玩家才通过。玩家身后的掩体不应阻止提示。
- `BP_TrainingController.StartCombat` 原先没有恢复独立躲避阶段修改的 QTE 开关。现在在设置战斗待启动状态前恢复 `SavedQTE`，涵盖预演、最终战斗及重试，并尊重进入教程前的禁用设置。

后续用户明确要求 360° 预警：已从 `EvaluateProjectileThreat` 删除相机位置、朝向、点积阈值判断及其布尔门。任意方向的候选来弹都进入原有弹道和遮挡检测。70 点能量门槛、提示时长、冷却及时停倍率保留；旧 `ThreatViewDotThreshold` 属性为兼容已有资产保留，但不再参与判断。
