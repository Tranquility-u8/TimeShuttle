# Story Jump 主线调试入口

单人玩法中按 **F10** 打开 Debug Menu，选择 **Story Jump** 的落点，再点 **Jump**。每次跳转重新加载目标关卡，从登记的任务入口开始。新关卡会按该剧情原有的任务链继续处理对话、目标、检查点、交互和转场。开发者也可以在玩法世界中运行 `TS.StoryJump <Id>`，两种入口调用同一段逻辑。

## 新流程接入

在 `Config/DefaultGame.ini` 的 `[TimeShuttle.StoryJump]` 添加一行 `+Points=`。用现有分组，或添加 `[TimeShuttle.StoryJump.<Group>]` 并写入关卡包路径 `Map`、原有主线会话 `Options` 和任务实例的生成类路径 `FlowClass`。

| 字段 | 用途 |
| --- | --- |
| `Id` | 稳定且唯一的调试入口 ID，可用于控制台和自动验证。 |
| `Label` | 下拉框显示名称。 |
| `Group` | 目标关卡、会话选项和任务类的配置。 |
| `Step` | 该任务实例中唯一的原生 `StepId`。跳转在任务第一次执行前设置 `StartStep`，由原有 `PrepareFlow` 和 `StartFlow` 初始化。 |
| `Checkpoint=true` | 要求入口任务明确标记为检查点。 |
| `Anchor` / `Face` | 可选。使用任务 `Roles` 或任务上的 Actor 引用指定地面锚点和朝向目标。关卡已有入场定位时留空。 |
| `Prepare` | 可选。填写目标任务蓝图中的无参数函数名。用它初始化跳过前序节点后仍需存在的装备标志、场景交互与表现。函数可返回布尔值来报告失败。 |
| `Pickup` | 可选。填写拾取物生成类路径，或分组里声明的配置信息名。分组同时声明 `EquipmentClass` 和原生装备槽 `EquipmentSlot`。系统用原生拾取和切换武器接口，等玩家装备就绪才启动任务。 |

先定义玩家到达时应看到的任务、允许的输入和应存在的场景状态。选择可独立启动的原生任务入口。需要前序状态时，把准备逻辑放在拥有该状态的流程内，让入口在新的关卡实例中可重复使用。遇到不可独立启动的演出，登记能自然进入演出的上游任务。

每个入口至少从另一张地图跳入一次，并检查目标地图、角色位置、首个原生任务和任务继续条件。再通过真实的目标区域、交互、对白或战斗入口推进到下一任务；跨图交接验证后继地图收到原有会话选项。记录使用的测试夹具、被触发的原生入口和任何未实测的后续流程。修改任务 ID 或入口依赖后，对应落点一起验证。

第一章旧流程的入场变量由插件内的章节准备逻辑补齐。后续关卡优先使用所属蓝图的准备函数。调试入口通过正常旅行创建会话，后续游玩沿用关卡自己的进度处理。用独立测试存档验证需要写入进度的流程。

## 当前覆盖与验证

配置登记了 17 个独立入口，包括第一章的苏醒、低矮通道、管道与第二房间、主控室路线、Omen、调节器、训练入口、八个训练检查点，以及训练返回简报和部署控制台。UE 5.6 PIE 对这 17 个入口逐项核对了目标关卡、原生任务、续接状态和需要的手枪。面板实点验证从 `Map_Test` 进入训练 S1。

进一步验证了低矮通道进入管道任务、第二房间触发开场并推进至门口任务、调节器交互后推进至训练路线，以及训练入口和部署控制台的实际转场。训练 S7A 清敌后进入 S7B，S7B 清敌后完成训练，并通过原有 `ChapterReturn` 转场回到第一章简报。接续测试使用角色定位、原生交互调用和对真实生成敌人的伤害注入。验证记录位于本地 `Saved/Agent/StoryJump/`。整章逐节点手动通关与打包构建尚未覆盖。
