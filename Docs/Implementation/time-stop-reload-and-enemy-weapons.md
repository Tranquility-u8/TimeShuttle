# 时停换弹与教程敌人武器清理

2026-10-23。延续 QTE 修复后的当前分支；本次不修改 QTE 判定、关卡布局或存档。

## 原因与修改

- `BP_Weapon_AutomaticBase` 的普通/空膛换弹通过世界时间 Delay 释放 `Reloading`，而玩家动画使用时间补偿。修复前 PIE 在世界倍率 0.01 下，四秒后弹匣已有 12 发，但 `Reloading` 仍为 true。
- 两条换弹完成路径改为记录现实时间截止点，仅在等待期间逐帧检查，随后执行原来的弹药结算与状态复位。换弹中进入/退出时停不会把已开始的等待拉长或缩短为世界时间倍数。
- `BP_Weapon_ShotgunBase` 的逐发装填定时器及空膛起始动画 Delay 存在同类问题，均改为玩家时间等待。保留原有装填数量、弹药消耗和中断决策；仅在 `Reloading` 为 true 时继续下一发。
- 敌人武器是单独生成、附着到角色的 Actor，附着关系没有提供 Actor 生命周期清理。修复前销毁射手后，步枪对象仍存活。`BP_Enemy_Base.EndPlay` 现检查并销毁 `WeaponActor`，已移除或未装备武器时安全跳过。
- `AC_TrainingVisual` 原来只隐藏教程主体，没有同步独立武器。新增 `SyncNativeWeaponVisibility`，在主体更新隐藏状态后同步原生敌人的武器。可回溯的死亡阶段保留武器对象，最终销毁由敌人的 EndPlay 负责；恢复主体可见性时武器也恢复。

## 验证与边界

本地证据保存在忽略跟踪的 `Saved/Agent/ReloadDeath20261023/`。测试使用实际 PIE、生产武器与敌人类；换弹/射击使用 Enhanced Input 动作注入。武器、武器栏数据对象、动画数据及射击靶体由测试夹具准备，不替代完整拾取流程验收。

- `baseline.json` / `retest.json`：同场景证明换弹锁从未释放变为正常释放，销毁敌人后的遗留武器从有效变为无效。
- `reload-suite.json`：普通/空膛换弹，Normal、FullStop、BulletTime，以及换弹中进入/退出时停；检查换弹锁、弹匣、真实射击输入消耗弹药、FullStop 悬浮弹丸。
- `shotgun-suite.json`：FullStop 普通/空膛装填及装填中切换时间模式，检查装填完成及后续开火。
- `death-suite.json`：教程 S7B 战斗入口生成四个敌人，通过实际伤害入口注入致死伤害，检查消隐、武器可见性恢复、最终销毁及武器已提前销毁的分支。可见性恢复是定向测试，不声称完成回溯输入的全链验收。

早期后台测试因编辑器低帧率与世界步长限制，在尸体原有消隐结束前取样，前台重测后通过。早期武器夹具缺少程序动画数据，且误把武器栏数据引用设为 Actor；已改为实际 PDA_Item 对象并重测；这些观测/夹具错误与正式逻辑问题分开记录。

完整教程从首关走到最后一关的人工试玩、换枪/菜单暂停期间的换弹体验以及打包版本仍未验收。原始资产备份位于上述本地证据目录的 `backup/`，回滚应先关闭或卸载相关资产，再恢复对应版本，不能直接编辑资产字节。

最终换弹回归仍观察到原有 `BP_Item_Base.SelectShotComponent` 在射击未命中时访问空 TargetActor，以及武器单节点播放 additive 动画的警告。本次未修改这些路径，不把日志描述为全部无错误；打包射击表现需另行验证。
