# Chapter 1 房间白盒到 UE 美术实景的工作流

第一房间在手工编辑的 `/Game/Maps/Map_LabV39` 原图完成替换。以下步骤适用于已有可玩白盒的房间。地板、通道、道具位置和演出状态取自当前关卡；概念图用来决定轮廓、材质、照明和损伤的表现。

## 1. 留下能回到现场的基线

确认编辑器打开的地图、要处理的房间和当前未保存的修改。先留存磁盘版本；如果现场有尚未落盘的布局，定向保存当前关卡，再另存一份现场快照。修改既有网格时，同时留存会被覆盖的 UE 资产及其 FBX 源文件。恢复时按本次修改范围取用同一阶段的备份。第一房间整房替换和斜板、风管返修各有独立恢复点。[整房替换前现场](../../../output/time-shuttler/ch1-room1-installed/backup/20261107-151149/Live/Map_LabV39.umap) · [局部返修前备份](../../../output/time-shuttler/ch1-deck-duct-repair/backup)

从玩家入口、主通道和看清遮挡关系的一侧拍下白盒。保存每个机位的世界位置、旋转、视场角及画幅。用完整地面和顶板取景；看不清连接处时增加侧视或近景。选定一条需要保护的玩家路线，记录地面高度、跳上平台的落点、狭窄处净空，以及角色能否走过或蹲过。[第一房间七个固定机位](../../../output/time-shuttler/ch1-offline-chambers/cameras.json)

## 2. 先把每个块解释清楚

沿玩家路线登记各块的实例、可见网格组件、父级、尺寸、朝向、材质与碰撞。量取组件的真实几何边界，尤其留意偏轴模型、旋转斜板和变形的管段。相近的白盒颜色可以提示设备分组，具体功能再用位置和连接关系核对。

给每块写一句用途，并标明它接向哪里、由什么支撑、玩家从哪一侧通过。第一房间的短舱与主舱之间只有一组短接头，主舱与后舱之间是五根连接杆；三个舱体纵向排列，断裂集中在主舱。这个关系决定了模型数量、接头朝向和损伤位置。制作预览时并排看同机位白盒与概念图，逐项核对门、地板、支脚、接头和通道边界。[第一房间三路对照](../../../output/time-shuttler/ch1-room1-installed/index.html)

## 3. 在原场景安装可编辑资产

低模机柜、灯具、墙板可以复用，玩家会靠近的关键设备优先制作观察窗、卡箍、支承、破口等能解释功能的细节。导入后在 UE 检查轴心、单位、材质槽和实际包围盒，再把模型对齐到原实例。已有斜面或异形件的轮廓合用时，可以只换材质。

静态装饰可沿用白盒碰撞，另挂关闭碰撞和导航影响的美术网格。地面和墙壳保持原支撑高度与洞口，面板接缝在网格上留出实际凹槽。带触发、物理或时停逻辑的对象，先确认蓝图持有的组件和替换入口，再决定如何换外观。第一房间的 FBX 和贴图保存在项目的 `SourceAssets`，UE 内可从既有资产重新导入。[可重导入源文件](../../SourceAssets/Chapter1/ParticleLab) · [第二房间已有演出与替换入口](chapter1-room2-cinematic.md)

## 4. 同机位复拍，进游戏走一遍

保存本次关卡和受影响资产，重开原图。从固定机位比较**原白盒、当前 UE 实景、概念参考**。先对齐玩家可达处、设备轮廓和前后遮挡，再调光色与材料。把可以从入口看见、但要走近才能判断的问题单独回拍。

| 第一房间遇到的问题 | 复查方式与已验证结果 |
| --- | --- |
| 斜板远看正常，近看有大片闪斑 | 用正视和贴近板面的斜角复拍，再检查引擎实际渲染网格。修复后 299 个板面采样点均只有一层顶面，分板线仍清楚。 |
| 三段悬空风管在转弯处露出整圈背景 | 从侧面和管内各看一次，核对内外截面对接、外壳局部撕裂和内壁净空。角色从管口内侧起步，实际蹲行通过两个弯头。 |
| 美术包覆可能垫高地板、挤占右侧通道 | 替换前后比较同一组碰撞查询。第一房间 43 项结果一致，实际玩家角色走完约 14.9 米右侧通道。 |
